# Importing Files

Importing creates the source and target files you translate in Codex. Use **source import** when you are adding original content. Use **target import** when you already have a translation and want Codex to align it to an existing source file.

## Open the Import Wizard

1. Open **Navigation** from the compass icon.
2. Click **Add Source File** to import original content.
3. Or click **Import Target File** to import an existing translation for a source file already in the project.

The wizard first asks whether you are working with source files or target files, then shows the importer picker.

## Source vs Target Imports

| Import type | Use it when | Result |
| --- | --- | --- |
| **Source Files** | You are adding content to translate. | Codex creates source files and blank target `.codex` files. |
| **Target Files** | You already have translated content. | Codex aligns the translation to existing source files. |

<Callout type="warning">
Import target files only after the matching source file already exists in the project.
</Callout>

## Active Importers

Importers are grouped by general-purpose and specialized workflows. The exact list can change by release, but these are the active user-facing categories in the current editor.

### Essential Importers

| Importer | Formats | Notes |
| --- | --- | --- |
| **Audio** | `.mp3`, `.wav`, `.m4a`, `.aac`, `.ogg`, `.webm`, `.flac` | Creates audio-linked cells for transcription or translation workflows. |
| **Subtitles** | `.vtt`, `.srt` | Preserves cue timing for subtitle translation and export. |
| **Word Documents** | `.docx` | Supports round-trip export back to DOCX. Long passages can be split into properly sized cells during import. |
| **Markdown** | `.md`, `.markdown`, `.mdown`, `.mkd` | Supports round-trip Markdown workflows and image handling. |
| **TMS Files** | `.tmx`, `.xliff`, `.xlf` | For localization and translation-memory workflows. |
| **InDesign** | `.idml` | Supports layout-oriented round-trip workflows. |

### Specialized Importers

| Importer | Use for |
| --- | --- |
| **USFM** / **USFM Biblical Texts** | Scripture projects from USFM or SFM files. |
| **Paratext Projects** | Complete Paratext archives. |
| **eBible Download** | Downloading open-license scripture resources. |
| **Macula Bible** | Hebrew and Greek source texts with linguistic annotations. |
| **Bible Stories** | Open Bible Stories Markdown and ZIP workflows. |
| **Biblica Study Notes** | Biblica IDML study note projects. |
| **Bible Spreadsheet with Audio Data** | CSV or TSV scripture workflows with audio URL columns. |

<Callout type="info">
PDF import is not currently an active import path in the importer picker. If you need PDF content, convert it to a supported source format before importing.
</Callout>

## Example: Import a USFM Source File

1. Open **Navigation**.
2. Click **Add Source File**.
3. Choose **Source Files**.
4. Select **USFM**.
5. Upload the `.usfm` or `.sfm` file.
6. Review the import summary.
7. Continue to the system message step if Codex asks for AI instructions.
8. Click **Start Translating** when import finishes.

## Example: Import Existing Translations

1. Import the source file first.
2. Open **Navigation**.
3. Click **Import Target File**.
4. Choose the source file this translation belongs to.
5. Choose the importer that matches the translation file.
6. Review the alignment preview.
7. Apply the import when the matches look correct.

## Alignment Methods

Target imports may use different matching strategies depending on the file type:

- **ID-based matching** for structured content with stable references.
- **Sequential insertion** for document-style formats.
- **Timestamp matching** for subtitles and media workflows.

Always review imported target content before continuing translation work.

## Re-import an Updated File

Use a re-import when the original document was revised, or when a newer Codex release fixes an import problem in a file you imported earlier.

Import the file as usual. If Codex recognizes it as a file already in the project (same file contents or same file name), the importer opens an **Already imported** step before writing anything. This works for importers that keep the original file, such as DOCX, Markdown, OBS, TMS, InDesign, and USFM. Bible books that already exist under their standard book name still use the overwrite prompt instead.

Under **What this import changes**, Codex lists:

- **New cells**: cells added in place. Surrounding cells and their translations stay put.
- **Changed cells needing review**: cells whose source changed, so the existing translation may no longer fit.
- **Cells no longer in the document**: cells hidden from the editor and from exports. Their content and history stay in the file.

Under **How should we import it?**, choose one:

- **Create new updated file**: keeps the existing file untouched and adds a new copy that carries your translations and the changes. This is the safest option.
- **Rewrite the existing file**: applies the changes to the existing file in place. Translations are kept, but the file's cells are rebuilt from the new import.
- **Import as a new file**: ignores the existing file and imports a separate, untranslated document.

Then select **Continue**.

When cells still match, Codex keeps their translations, edit history, comments, and audio. Each changed cell gets a yellow bar on its left edge in the editor, and milestone navigation shows how many cells in each milestone need review. The flag clears when you edit or validate the translation. If a changed cell had been validated, Codex removes that validation so someone checks it again.

## Round-trip Workflows

Round-trip importers keep enough original structure to export back to the original format. Common examples include DOCX, IDML, USFM, Markdown, OBS, TMS files, CSV/TSV, and Biblica workflows.

See [Exporting Projects](/docs/translation/exporting-project) for the export side of round-trip workflows.

<Accordion title="Troubleshooting imports">

### The file is not recognized

Check the file extension, confirm the file opens in its original application, and make sure it is not password-protected or corrupted.

### Imported translations do not align well

Confirm you selected the correct source file. If the preview offers multiple alignment methods, try the one that best matches the source structure.

### Formatting or images are missing

Use a round-trip importer when you need to preserve structure and media. Some importers intentionally simplify formatting so translators can focus on text.
